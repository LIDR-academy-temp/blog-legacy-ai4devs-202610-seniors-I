Alcance: crear, editar, borrar y listar comentarios, en la API (`backend/start/routes.ts`), la tabla (`backend/database/migrations/1769000000005_create_comentarios_table.ts`, más la semilla `backend/database/seeders/blog_seeder.ts`) y la web (`frontend/src/componentes/Comentarios.jsx`, `DetallePost.jsx`, `ListaPosts.jsx`, `PostsRelacionados.jsx`). Reglas contrastadas: (a) un comentario pendiente no se muestra en el detalle; (b) el recuento cuenta solo aprobados; (c) la respuesta pública no expone el correo de quien comenta.

## Cómo se aprueba un comentario

No existe ninguna forma en el código. No hay ruta que cambie `estado`: el PATCH solo escribe `cuerpo` (`routes.ts:388`), el único `INSERT` fija `'pendiente'` (`routes.ts:326`), y el valor `'aprobado'` solo aparece en lecturas y en la semilla (`blog_seeder.ts:487`). Un comentario nuevo queda pendiente para siempre salvo que alguien lo cambie a mano en `backend/tmp/db.sqlite3`, fuera de cualquier código revisable. Ver hallazgo 4.
