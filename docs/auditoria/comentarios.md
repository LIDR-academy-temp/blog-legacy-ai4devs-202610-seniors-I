# Auditoría de la feature «comentarios»

Alcance: las tres capas de la feature y nada más.

- **API:** `POST /posts/:slug/comentarios`, `PATCH /comentarios/:id`, `DELETE /comentarios/:id`, y el listado, que vive dentro de `GET /posts/:slug` (`backend/start/routes.ts`).
- **Base de datos:** la tabla `comentarios`, `backend/database/migrations/1769000000005_create_comentarios_table.ts`.
- **Web:** `frontend/src/componentes/Comentarios.jsx`, más el recuento de `DetallePost.jsx`.

Todas las rutas son de `backend/start/routes.ts`, salvo que se indique otro archivo.

**Cómo se comprobó.** Claude leyó el código y probó los comportamientos contra la API real (`make api`, 3401), sobre una copia de la base. Un hallazgo marcado con ✔ **se ejecutó y se vio**. Uno marcado con 👁 **solo se leyó en el código**. En el segundo caso la columna 3 es una deducción y no una observación. La web no se abrió en un navegador, así que todo lo del frontend es 👁.

**Orden:** por prioridad, de mayor a menor. La prioridad pondera el daño a un usuario real, si hay datos o permisos en juego, y el coste de arreglarlo.

No se ejecutó ni a favor ni en contra.
