# Auditoría de la feature de comentarios

Blog «Corriente» · cohorte 202610-seniors-I · rama `auditoria-AF`

**Alcance:** la feature de comentarios de punta a punta — crear, editar, borrar y listar comentarios
— en sus tres capas: rutas de la API ([`backend/start/routes.ts`](../../backend/start/routes.ts)), tabla en la base de datos
(`backend/database/migrations/`) y lo que la web enseña de ella (`frontend/src/componentes/`).
Fuera de alcance: posts, autores, categorías y etiquetas, salvo cuando un comentario es el modo en
que se rompen.

**Cómo se verificó:** cada hallazgo de esta tabla se comprobó ejecutando el caso contra la API
levantada (`curl`), contra la base (`sqlite3`) y contra la web en el navegador. Ninguna fila se
apoya solo en lectura de código. La línea citada en cada fila es la que lo demuestra.

**Nota sobre "¿se deshace con un revert?":** se entiende por *revert* el `git revert` del commit que
arregla el hallazgo. La respuesta es "sí" cuando el arreglo es solo código y la vuelta atrás deja el
sistema como estaba; "no" cuando el arreglo mueve datos y la vuelta atrás deja la base en un estado
que el código ya no contempla.

### Notas de alcance

- **No hay XSS en los comentarios.** El cuerpo del comentario se pinta como texto de React
  ([`frontend/src/componentes/Comentarios.jsx:61`](../../frontend/src/componentes/Comentarios.jsx#L61) — `<p>{c.cuerpo}</p>`), que escapa. El `dangerouslySetInnerHTML`

  porque el cuerpo del post sí pasa por `aHtml()` sin sanear.
- **La validación del email es laxa** ([`backend/start/routes.ts:316`](../../backend/start/routes.ts#L316) — `String(email).indexOf('@') === -1`:
  acepta `a@`, `@b`, `a@b@c`), pero con el correo sin publicar en ninguna respuesta (H1 resuelto) el
  daño es pequeño. Queda anotado, no priorizado.
- **La regla 2 sí se cumple**: un comentario `pendiente` no aparece en el detalle
  ([`backend/start/routes.ts:153`](../../backend/start/routes.ts#L153)). Y la regla 3 (`slug` único) y la 4 (los relacionados no se incluyen
  a sí mismos) también se cumplen: [`backend/start/routes.ts:191`](../../backend/start/routes.ts#L191) filtra `id <> ?`. Se comprobaron
